# logdrop — design spec

Status: approved for planning (2026-09-23)
Origin: [MarvellousSuspender#518](https://github.com/gioxx/MarvellousSuspender/issues/518)

## 1. Purpose

A small, generic, self-hostable **PrivateBin-style drop-off for plain text** (logs, diagnostic dumps, any paste), where:

- Anyone can upload text (paste or `.txt` file) with no account.
- Only an allow-listed set of maintainer emails can ever read an upload.
- Uploads expire automatically after a configurable retention window, or can be deleted early by a maintainer.

Born from a MarvellousSuspender need (bug reporters currently paste `captureLogs`/`debug.html` diagnostic dumps into public GitHub comments, leaking personal data — tab URLs/titles, file paths). Scoped as a standalone, project-agnostic tool rather than a TMS-specific feature, since the same need is generic. **TMS/extension integration is explicitly out of scope for v1** — see Section 8.

## 2. Non-goals (v1)

- Not a general file-sharing service. Text only, no binaries, no images, no archives.
- No database. All state lives in Vercel Blob.
- No revocable server-side sessions (rotate the signing secret to force global logout instead).
- No dedicated rate-limiter service. Turnstile + size cap + kill-switch instead (Section 6).
- No client-side encryption (PrivateBin-style zero-knowledge). Reads are already auth-gated server-side; this is out of scope unless a future need justifies it.

## 3. Architecture

- **Repo**: `Marvellous-Codeworks/logdrop`, public.
- **Stack**: TanStack Start + TanStack Router + Vite + Bun + TypeScript — matches `marvellous-codeworks-home` tooling conventions.
- **Hosting**: its own Vercel project/deployment, independent of any other site. Custom domain (e.g. a personal `capturelogs.*` CNAME) is deployment config, not part of the repo.
- **Storage**: Vercel Blob only — no Postgres/KV/Redis.
- **Email**: Resend, for magic-link delivery only.
- **Abuse mitigation**: Cloudflare Turnstile (works regardless of the domain's DNS provider) + Vercel Edge Config for a runtime kill-switch.

### Routes

| Route | Access | Purpose |
|---|---|---|
| `GET /` | public | Frontpage: paste text or upload a `.txt` file |
| `POST /api/upload` | public | Accepts a paste, validates, stores, returns the full share URL |
| `GET /r/:slug` | **auth-gated** | Renders the paste as escaped text; redirects to login if not authenticated |
| `GET /admin` | **auth-gated** | Dashboard: list of uploads, expiry, uploader info, delete action |
| `GET /admin/login` | public | Email entry form |
| `POST /admin/login` | public | Validates email against `ADMIN_EMAILS`, sends magic link via Resend |
| `GET /admin/verify?token=` | public (token-gated) | Verifies the magic-link JWT, sets the session cookie |
| `POST /api/cron/cleanup` | Vercel Cron only | Deletes expired uploads |

## 4. Data model (Vercel Blob, no DB)

Each upload gets a random, unguessable `slug` (e.g. 12-char url-safe id) and exactly two blobs:

- `uploads/<slug>/content` — the paste body. Content-type is **always forced** to `text/plain; charset=utf-8` server-side, regardless of what the client claims.
- `uploads/<slug>/meta.json`:
  ```json
  {
    "slug": "string",
    "createdAt": "ISO 8601",
    "expiresAt": "ISO 8601",
    "sizeBytes": 12345,
    "originalFilename": "string | null",
    "label": "string | null",
    "uploaderIp": "string | null",
    "uploaderCountry": "string | null",
    "userAgent": "string | null"
  }
  ```

`expiresAt = createdAt + RETENTION_DAYS` (env var, default `7`), computed once at upload time. `originalFilename` and `label` are informational only — never used to derive a served filename, content-type, or file path.

The dashboard lists uploads via `list({ prefix: "uploads/" })`, pairs `content`/`meta.json` by slug, and sorts by `createdAt` desc. Deleting an upload removes both blobs immediately.

## 5. Content handling — text only, never a served file

This is a hard constraint, not a nice-to-have:

- On upload, the server reads the body and validates it decodes as UTF-8 text with no null bytes / binary markers. Anything that fails is rejected with a clear error — regardless of the extension or `Content-Type` header the client sent.
- `/r/:slug` never triggers a file download. It renders the paste inside an escaped `<pre>` block on a normal web page (like PrivateBin's paste view) — never interpreted as HTML, to prevent XSS via paste content.
- An optional "Download as .txt" button is **client-side only**: it builds a `Blob` from the text already rendered on the page and triggers a save with a filename generated by the app (`logdrop-<slug>.txt`). The uploader's original filename is never used for this.
- No support for any other file type. The frontpage's file input restricts to `.txt`/`text/plain` for UX; the real enforcement is the server-side text validation above.

## 6. Auth (magic link, stateless)

- `ADMIN_EMAILS` env var: comma-separated allow-list.
- Login: user submits an email on `/admin/login`. If it's in `ADMIN_EMAILS`, the server signs a JWT `{ email, exp: now + 15m }` (stateless — no server-side token storage) and Resend emails a link to `/admin/verify?token=...`.
- Verify: the server checks the JWT signature, expiry, and that the email is still in `ADMIN_EMAILS`, then sets an httpOnly, secure session cookie — itself a signed JWT `{ email, exp: now + 7d }`.
- Session is fixed 7-day expiry, no sliding renewal. After expiry, re-request a magic link.
- No revocation list for v1: to force a global logout, rotate the JWT signing secret env var.
- Every `ADMIN_EMAILS` email has identical dashboard access — no per-user roles for v1.

## 7. Abuse mitigation

- **Cloudflare Turnstile** widget on the public upload form (`/`), verified server-side via Turnstile's siteverify API on `POST /api/upload`. Independent of the domain's DNS provider.
- **`MAX_UPLOAD_BYTES`** env var (sane default, e.g. 5MB) enforced server-side before storing.
- **Kill-switch**: a Vercel Edge Config flag (`uploadsDisabled`) checked on every `POST /api/upload`, readable/updatable at runtime with no redeploy, as an emergency shutoff for public uploads.
- No dedicated rate-limiter in v1 (would need a KV solely for that) — revisit only if abuse is observed in practice.

## 8. Explicitly deferred

- MarvellousSuspender extension integration: an "Upload report" button in `src/js/debug.js` (next to the existing `btnCopyReport`/`btnDownloadReport`, reusing `buildReport(true)`) that POSTs directly to `logdrop`'s `/api/upload` and shows the returned URL in the diagnostic page. Needs its own design pass later (CORS/host_permissions, how to handle Turnstile or an alternative gate for non-browser-form callers, response UX).
- Multi-tenant / per-user upload quotas, roles, or dedicated rate-limiting.
- Any file type beyond plain text.

## 9. Testing plan

- Unit: text-validation function (accepts valid UTF-8 text, rejects binary/null-byte content regardless of claimed type); slug generation collision resistance; retention date math.
- Integration: upload → stored as forced `text/plain` with correct `expiresAt`; `/r/:slug` returns redirect-to-login when unauthenticated and renders escaped content when authenticated; cron cleanup deletes only past-`expiresAt` uploads and leaves others untouched; admin delete removes both blobs immediately.
- Auth: magic-link JWT rejected once expired or once email is removed from `ADMIN_EMAILS`; session cookie rejected once expired; login rejected for emails not on the allow-list (without leaking whether the email was tried).
- Manual: Turnstile blocks a scripted upload without a valid token; kill-switch flips `POST /api/upload` to reject without a redeploy.
